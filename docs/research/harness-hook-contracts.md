# Harness hook contracts

Research record for `jact setup` and `jact hook`, gathered 2026-11-19. It states what each harness was observed to do and where the observation came from. The steps for users are in [Wire jact into an agent harness](../harness-hooks.md#Wire%20jact%20into%20an%20agent%20harness).

Tags: `#OBS` means seen in a command output, a file, or a named document. `#A` means believed but not verified. `#H` means a claim with a test that can refute it.

## What each harness was observed to do

| Harness | Hook point | Event sent to the hook | How text returns to the model |
|---|---|---|---|
| Claude Code 2.1.328 | `hooks.PostToolUse` in `.claude/settings.json`; matcher on tool name | JSON on standard input: `tool_name`, `tool_input.file_path`, `cwd`, `session_id` | `{"decision":"block","reason"}` or `hookSpecificOutput.additionalContext` |
| Codex 0.160.0 | `hooks.PostToolUse` in `.codex/hooks.json`; tool name `apply_patch` | JSON on standard input: `tool_input.command` holds the patch text; file names are on `*** Add File:` lines | The same two shapes as Claude Code |
| Antigravity CLI 1.5.12 (`agy`) | One hook name as a top-level key in `.agents/hooks.json`; events `PostToolUse`, `PreInvocation`, `Stop`; the tool matcher is a regular expression | JSON on standard input: `toolCall.name`, `toolCall.args.Path`, `cwd`, `workspacePaths`, `conversationId`, `hookEventName`, `error` | `PostToolUse` must answer `{}`. `PreInvocation` answers `{"injectSteps":[{"systemMessage":{"systemMessage"}}]}`. `Stop` answers `{"decision":"continue","reason"}`. |
| Gemini CLI 0.41.2 | `hooks.AfterTool` in `.gemini/settings.json`; matcher is a regular expression | JSON on standard input: `tool_name`, `tool_input`, `tool_response`, `session_id`, `cwd`, `hook_event_name`, `timestamp` | `hookSpecificOutput.additionalContext`, appended to the tool result |
| pi 1.4.0 | `.pi/extensions/<name>.ts`; `pi.on("tool_result", handler)` | `event.toolName`, `event.input.path`, `event.content`, `ctx.cwd` | The handler returns `{content, isError}` |
| omp 19.0.0 | `.omp/extensions/<name>.ts`; the same `tool_result` event | The same fields as pi | The same return value as pi |

## Evidence

- #OBS Claude Code, Codex, pi, and omp each ran a live session in which the installed hook caught a broken link. Claude Code, pi, and omp also added linked content on a read. [^live]
- #OBS Antigravity CLI 1.5.12 ran live sessions in which the installed hooks caught a broken link and added linked content on a read. The evidence is in [Antigravity CLI 1.5.12 in live sessions](#Antigravity%20CLI%201.5.12%20in%20live%20sessions).
- #OBS Gemini CLI builds the `AfterTool` event from `tool_name`, `tool_input`, and `tool_response` plus five base fields, and appends `additionalContext` to the tool result. [^gemini-code]
- #OBS Gemini CLI 0.41.2 could not start a model session: the server answered `UNSUPPORTED_CLIENT` for the signed-in account. The latest published version is 0.69.0. [^gemini-login]
- #OBS Google replaced Gemini CLI with Antigravity CLI on 2026-06-18 for unpaid, Google One, and Google AI Pro and Ultra accounts. Gemini CLI still serves paid API keys and enterprise accounts. [^agy-transition]
- #A That change caused the refusal, not the age of the installed CLI. An update of Gemini CLI does not fix it for this account. An earlier draft of this record said the opposite. Risk if wrong: none for the design, because `jact setup gemini` stays for the accounts that Gemini CLI still serves.
- #A A current Gemini CLI still sends `tool_input.file_path` for `write_file`, `replace`, and `read_file`. Risk if wrong: the Gemini hook stays silent. Cost to verify: one run of `node scripts/hooks-e2e.mjs gemini` with an account that Gemini CLI still serves. The parser also accepts `path` and `absolute_path`.
- #OBS pi skips a project's extensions until the project is trusted. Print mode cannot show the prompt, so it needs `--approve`. [^pi-trust]
- #OBS Codex ran the project hook only with `--dangerously-bypass-hook-trust` and a trusted project in a run without a UI. Codex has no read event: it reads files through shell commands. [^live]
- #OBS A user-level `~/.codex/hooks.json` can already hold hook entries from another tool on five events, so setup must merge and never overwrite. [^codex-existing]
- #OBS Codex's `workspace-write` sandbox keeps a project's `.codex` folder read-only. It refused `jact setup codex` and Codex's own patch tool. So Codex cannot wire itself. [^codex-sandbox]
- #A In an interactive Codex session, the user can approve the command to run outside the sandbox. Risk if wrong: none for the guide, which tells the user to run the command in a terminal. Cost to verify: one interactive session.
- #OBS An agent that had only the README and the guide wired its own harness on the first attempt: Claude Code in 15 seconds, pi in 14, omp in 90. Codex could not write the file and gave the user the command to run, in 73 seconds. [^readme-setup]
- #OBS Four agents found the setup command in the README in 3.6 to 9.9 seconds, each with the correct answer. [^readme-find]

## Antigravity CLI in its documentation

Each `#OBS` in this section is what a document states. jact's first Antigravity build came from these documents alone, before `agy` was on the test machine. Where a live session later settled a claim, the bullet says so, and the evidence is in [Antigravity CLI 1.5.12 in live sessions](#Antigravity%20CLI%201.5.12%20in%20live%20sessions).

- #OBS `agy` was not on the test machine at the first build, and its sign-in needs a browser. The machine's owner installed it and signed in later that day. [^agy-absent]
- #OBS The documentation states that hooks load from `.agents/hooks.json` in the project and from `~/.gemini/config/hooks.json` for the user. It states that hooks in `~/.gemini/antigravity-cli/settings.json` are not loaded. A separate test by another author found the same two files. [^agy-docs] [^agy-where]
- #OBS The documentation states the file shape. Each top-level key is a hook name that the user chooses. Its value holds event keys: `SessionStart`, `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop`. A tool event lists `{"matcher", "hooks": [{"type": "command", "command", "timeout"}]}`. The other four events list the command objects directly, with no matcher. [^agy-docs]
- #OBS The documentation states the input: camelCase JSON on standard input with `conversationId`, `workspacePaths`, `transcriptPath`, `artifactDirectoryPath`, `modelName`, and `lastUserInput`. `PostToolUse` adds `toolCall.name`, `toolCall.args`, `stepIdx`, and `error`, which is empty when the tool succeeded. The page names neither `hookEventName` nor `cwd`. [^agy-docs] [^agy-docs-steps]
- #OBS The documentation names the file tools and their path fields: `write_to_file`, `replace_file_content`, and `multi_replace_file_content` use `TargetFile`; `view_file` uses `AbsolutePath`. Version 1.5.12 sent other names. [^agy-docs]
- #OBS The documentation states the outputs of the two events that cannot add a step. `PostToolUse` "Returns an empty JSON object". `Stop` needs `decision`: the value `continue` keeps the agent running and gives `reason` to the model as a system message, and each other value lets it stop. [^agy-docs] [^agy-docs-steps]
- #OBS Three events may return `injectSteps`: `SessionStart`, `PreInvocation`, and `PostInvocation`. One step holds one of four fields: `systemMessage` (an object, "An out-of-band system instruction for the agent"), `userMessage` (text, "A message from you."), `ephemeralMessage` (text, "A transient system message."), or `errorMessage` (an object, shown to the user and not sent to the model). The page does not state how long an ephemeral message lasts. [^agy-docs-steps]
- #OBS The `systemMessage` object holds the text in a second field with the same name. The page's example value is `{"systemMessage": "Remember to lint", "metadata": {"source": "policy"}}`, and its `SessionStart` example nests the field the same way. Its `PreInvocation` example uses the ephemeral kind: `{"injectSteps": [{"ephemeralMessage": "Remember to lint"}]}`. [^agy-docs-steps]
- #OBS `PreToolUse` must answer with `decision`: `allow`, `auto_approve`, `deny`, `ask`, `force_ask`, or `deny_unless_prior_grant`. The page does not state what an empty object does. A hook's `timeout` defaults to 30 seconds. [^agy-docs-steps]
- #OBS Antigravity CLI 1.5.12 differs from its documentation in two places: the file tool names with their path fields, and two input fields that the page does not list. The project file, the file shape, the three events, and the three output shapes held in live sessions. At the first build this was an `#A`. [^agy-live-probe] [^agy-live-pass]
- #A A Gemini CLI `AfterTool` hook does not run in `agy`. The documentation lists six events, and `AfterTool` is not one of them. It also does not list `.gemini/settings.json` as a hooks file. So `jact setup gemini` does nothing for Antigravity CLI. Risk if wrong: none, because `jact setup antigravity` writes a different file.
- #OBS `PreInvocation` runs before each model call, so the model gets jact's result at its next step. At the first build this was an `#H`, with the rival that the hook runs one time for each user turn. The live probe recorded one hook call for each model call. [^agy-live-probe]
- #OBS The model reads an `ephemeralMessage` for one model call only. At the first build this was an `#A` with no limit in it, and jact used that kind. jact now uses a system message. [^agy-persist]
- #A A hook that prints valid JSON and exits 0 never stops `agy`. When jact has nothing to say it prints `{}` for `PostToolUse` and `PreInvocation` and `{"decision":"stop"}` for `Stop`, and each live session ran to its end with those answers. The documentation does not state what a non-zero exit, text on standard error, or a timeout does. Risk if wrong: low, because jact always prints JSON and exits 0.
- #A An interactive `agy` session may ask the user to trust a workspace before it runs that workspace's hooks. One third-party guide says so; Google's hook page does not. Runs without a UI had no trust step. Risk if wrong: the project hook stays silent until the user trusts the folder. Cost to verify: the `/hooks` command in `agy` lists the hooks it loaded.
- #A The user-level file `~/.gemini/config/hooks.json` loads as the documentation states. No live session used it. Risk if wrong: `jact setup antigravity --global` wires nothing. Cost to verify: one session with that file, on a machine where a change to the user's own configuration is acceptable.
- #OBS The installed wiring passes with sample events. The check reads `.agents/hooks.json`, runs the command of each event, and confirms that the matcher selects the three tool names that version 1.5.12 sent and the four documented names, and not `run_command`. [^agy-synthetic]
- #OBS The live check can fail, so a pass means something. It ran against a stand-in program that plays the documented contract. It passed when the stand-in repeated what the hooks handed over. It failed when the stand-in ignored that text, and when the stand-in ran `PreInvocation` one time for each request. The stand-in is not Antigravity CLI: these runs test the check, not the harness. [^agy-standin]
- #OBS A `PreInvocation` call with nothing to hand over takes about 90 milliseconds, and a `Stop` call about 85. Antigravity CLI pays the first one before each model call. [^agy-cost]

## Antigravity CLI 1.5.12 in live sessions

`agy` 1.5.12 was installed and signed in on 2026-11-19. Where this section and the documentation section differ, this section is correct for version 1.5.12. A session id in a footnote is the first eight characters of that session's folder name under `~/.gemini/antigravity-cli/brain/` on the test machine.

### Tool names and hook inputs

- #OBS The file tools that reach a hook are `write_file`, `edit_file`, and `read_file`. Each carries the file in `toolCall.args.Path`, as an absolute path. Three model families sent the same names: Gemini 4 Neon, Gemini 3.8 Flash, and Claude Sonnet 5.5. [^agy-live-probe]
- #OBS The tool names in the documentation (`write_to_file`, `replace_file_content`, `multi_replace_file_content`, `view_file`) reached no hook in any run. `agy` still prints them in the tool list at the start of a `--output-format stream-json` run. [^agy-live-probe]
- #OBS The first live check failed for that reason. The model created the file, and `PostToolUse` did not run, because the matcher held only the documented names. [^agy-live-first]
- #OBS Each hook input names its event in `hookEventName` and its folder in `cwd`. The documentation lists neither field. [^agy-live-probe]
- #OBS `PreInvocation` runs before each model call: four calls for four model calls, with `invocationNum` 0 to 3. [^agy-live-probe]
- #OBS One model call can start two tools. The Claude model wrote one file and read one file in one step, and `PostToolUse` ran two times before the next `PreInvocation`. [^agy-live-probe]
- #OBS A `PostToolUse` hook that prints `{}` lets the session continue. `error` is an empty string after a tool call that succeeded. [^agy-live-probe]
- #OBS A `PreToolUse` hook that prints `{}` denies the tool call. `agy` reported "tool call denied by pre-tool hook". jact installs no `PreToolUse` hook. [^agy-live-pre]
- #OBS The `Stop` input adds `terminationReason` (the value was `NO_TOOL_CALL`), `fullyIdle`, `continuationActive`, `executionNum`, and `error`. [^agy-live-probe]
- #OBS `agy` ran the hooks of a new project folder in print mode with no trust step. [^agy-live-probe]
- #A The matcher finds a tool name anywhere in the text, or needs the whole name. The runs do not tell which: `.*` matched each tool. Risk if wrong: none, because jact's matcher lists whole names.

### How long a handed-over message lasts

jact skips the links that it already extracted in a conversation. So linked content that the model loses is gone: a second read of the same file returns nothing new. The kind of step that carries jact's text decides whether that happens.

- #OBS An `ephemeralMessage` reached the model for one model call. A probe hook handed over one token before one model call and a second token before the next. The model learned one call later that it needed them. The fast model answered `UNKNOWN` for both tokens in 2 of 2 runs, and each transcript shows both ephemeral steps. [^agy-persist]
- #OBS The default model answered both tokens in one run and only the first token in the next run. Its notes in that second run: "The deploy token "ZEBRA-7731" appeared in a prior thought, but is missing from the `write_file` tool response. This suggests either transient injection or non-persistence of the token data." [^agy-persist]
- #A The default model's correct answers came from its own earlier notes, not from the message. Support: the quote above. Risk if wrong: none for the design, because the fast model's result alone rules the ephemeral kind out.
- #H Rival, refuted: a second ephemeral message pushes out the first. The run that lost one token kept the older token and lost the newer. [^agy-persist]
- #OBS An ephemeral message did not reach the next turn of the same conversation. A control fact that the model read from a file in turn 1 came back in turn 2; the token did not. [^agy-turn]
- #OBS A step with plain text in `systemMessage`, `{"systemMessage": "<text>"}`, never reached the conversation. `agy` reported no error, the transcript holds no step for it, and the model answered `UNKNOWN` for both tokens in 2 of 2 runs. The documentation does not show that shape. [^agy-flat]
- #OBS A nested system message, `{"systemMessage": {"systemMessage": "<text>"}}`, stayed. The fast model answered both tokens in 2 of 2 runs, and the next turn of the conversation still held the token. [^agy-nested] [^agy-turn]
- #OBS `agy` wraps a nested system message before the model reads it. The wrapper says that the text was "not actually sent by the user" and "was injected by a PreInvocation hook". [^agy-nested]
- #A A `userMessage` step stays in the conversation too. It was not tested, because it presents jact's text as the user's own words. Risk if wrong: none, because jact does not use it.

**Decision:** `jact hook antigravity --event PreInvocation` answers with one nested system message. The cost is size: the text stays in the conversation, so the linked content of a read, up to 20,000 characters, counts toward each later model call. Each other harness has the same cost.

- #OBS With the ephemeral hand-over, the live check passed with the default settings and failed with `--sandbox`. The reply held the linked content and `NONE` for the report, although the hook log shows that jact handed the report over. [^agy-live-sandbox]
- #A The one-call lifetime caused that failure. Support: with the nested system message, the same check passed with `--sandbox` in 2 of 2 runs.
- #OBS With the nested system message, `node scripts/hooks-e2e.mjs antigravity` passed with the default model, with the fast model, with a Claude model, and with `--sandbox`. A pass means that the reply quoted the linked fact and the first line of the broken-link report, and that the hook log shows no read of the linked page. [^agy-live-pass]
- #OBS A Claude model did not repeat a "launch code" that a hook supplied. The check's first linked fact was "The launch code is 4242." Claude Sonnet 5.5 answered `UNKNOWN` for it in 4 of 4 runs, and it quoted the broken-link report in each of them. [^agy-claude]
- #OBS The model had read the text. Its words in one run: "The code, 4242, was in text attached to the file-read result and framed as a system message. It wasn't in docs/index.md, which only links to target.md#Details. I didn't open target.md, so I couldn't confirm the code from the linked section." [^agy-claude]
- #H Rival, refuted: the wording of the question caused the `UNKNOWN`. Two other wordings gave the same answer. [^agy-claude]
- #H Not refuted: the words "launch code" made the text look like a planted test of the model. Test: change the linked fact to a dull one and leave the hook as it is. Result: with "The staging server listens on port 4242." the same model answered `4242` in 3 of 3 runs. [^agy-live-pass]

### The Stop hook, the sandbox, and the README tests

- #OBS The `Stop` fallback works without `PreInvocation`. In a project whose hooks file had no `PreInvocation` entry, the model created a file with a broken link and stopped. The `Stop` hook answered `continue` with the report. `agy` gave the model the report after the words "Stop hook blocked termination: ", the agent ran one more time, and the second `Stop` call let it end. [^agy-stop]
- #OBS Hooks ran with `--sandbox`, also when the jact build was in a folder that the sandbox hides from the agent. [^agy-live-pass]
- #OBS `--sandbox` hides files under `~/Documents` from the agent's `run_command` tool, unless the agent sets `BypassSandbox` in the tool call. [^agy-self-setup]
- #OBS An agent that had only the README and the guide wired Antigravity CLI on the first attempt in 31 seconds. It ran `jact --version`, `jact setup antigravity`, and `jact setup antigravity --check`. [^agy-self-setup]
- #OBS With `--sandbox`, the same request passed in 53.6 seconds on the agent's second try. The jact build was under `~/Documents`, so the sandbox hid it. The agent ran the command again with `"BypassSandbox": true`. [^agy-self-setup]
- #OBS The agent found the setup command in the README in 10.7 to 11.5 seconds with the default model, and in 6.3 and 7.2 seconds with the fast model. Each answer was correct. The default model misses a 10-second target by 0.7 to 1.5 seconds. [^agy-find]
- #OBS A prompt that reads no file took 5.5 to 6.5 seconds in 4 runs, about half of the default model's time in the README test. [^agy-find]

## Prior art that shaped the interface

- #OBS graphify installs hooks with one function for each harness. Each function loads the existing JSON, removes its own earlier entry, appends a new entry, and writes the file. The hook command is the tool's own subcommand, `graphify hook-check`. jact copies both ideas. [^graphify]
- #OBS graphify replaces a config file that is not valid JSON with an empty object. jact refuses instead, so a typing error in a settings file cannot delete other tools' hooks. [^graphify]
- #OBS beads uses `bd setup <agent>` with the flags `--print`, `--check`, `--remove`, `--project`, and `--global`, and one source file plus one test file for each agent. jact copies the command name and the flag names. [^beads]
